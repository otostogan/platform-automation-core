# Platform Automation Core v0.30.0

One-off commands in the serving release, and an honest redeploy of it.

Release assets:

- `otostogan-platform-0.30.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.30.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform exec --project … --environment … [--service …] -- <command>`
  runs one command in a fresh container of the serving release, the way its
  migration runs: the release's image, its secrets with the platform's
  database URL, its networks, a container of its own, the command's exit
  code. The console offers it as "Run a script inside the application"
  with live output over SSH. `ops` only; the `deploy` user's allowlist is
  unchanged.
- Console Deploy: when the chosen tag is the release serving the environment
  now, the console says a plain dispatch would be a no-op on the host and
  offers to run the whole flow again — migrations, seeds, restart — under a
  new label. Without the host's answer it asks for a label instead, and the
  reusable deploy workflow warns in Actions when a dispatch was such a no-op.

Upgrade: pin `v0.30.0`, converge — `exec` is a host command and arrives
with the runtime. Then `platform update` in each application for the
deploy workflow's warning.

# Platform Automation Core v0.15.1

Makes bare `platform` on a host refuse cleanly instead of failing on an
import.

Release assets:

- `otostogan-platform-0.15.1.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.15.1-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- Convergence installs the runtime on a host from an explicit list of modules,
  and the operator console is deliberately not on it: it is workstation code.
  In `v0.15.0`, `platform` with no arguments — and `platform doctor`,
  `platform new` — imported that console before deciding it was on a host, so
  an operator typing bare `platform` over SSH got a `ModuleNotFoundError`
  traceback rather than the intended message. The check now runs in the CLI
  itself, before any import, and it needs no privilege: `/var/lib/platform`
  is root-owned and mode 0750, so `ops` cannot look inside it and the look
  is denied rather than answered — and a denied look is itself the answer,
  because a workstation has no such directory at all. On a host, bare
  `platform` says so and points at `sudo -n platform <command>`, exit code 2.
- Nothing else changed. `projects`, `status`, `backups` and the rest behave as
  in `v0.15.0`; the `deploy` account's sudoers entry is unchanged.

# Platform Automation Core v0.3.0

This release removes the single-operator dependencies that made recovery,
host enrollment, and incident handling impossible without one person.

Release assets:

- `otostogan-platform-0.3.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.3.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Highlights:

- enforces a configurable minimum of unique SOPS age recipients on every path
  that decrypts secrets: bundle build, `platform deploy`, `platform rollback`,
  and boot secret recovery, so key escrow cannot lapse unnoticed;
- counts unique recipients only, so a repeated key is never mistaken for a
  recovery key;
- refuses caller arguments that would lower the host recipient policy, and
  rejects non-positive policy values before any bundle is read;
- enrolls hosts in Tailscale non-interactively from a controller-local
  pre-authorized key that never enters inventory, the process list, or
  persistent disk, and is removed even when enrollment fails;
- adds an operations runbook covering deployment, rollback, releases stuck in
  `deploying`, `access_guard` recovery, reboot acceptance, and the recovery
  material a second operator needs;
- retains the `platform/v1` contracts, collection roles and playbooks, server
  CLI, nginx activation transaction, rollback, and reboot recovery behavior.

Upgrade notes:

The recipient policy ships disabled: `platform_cli_minimum_age_recipients`
defaults to `1`, so existing deployments are unaffected. Raise it to `2` only
after every deployable SOPS file carries both a primary and a recovery
recipient, otherwise the next deployment and the next reboot will be refused.

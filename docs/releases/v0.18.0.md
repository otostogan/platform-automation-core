# Platform Automation Core v0.18.0

An application can be taken off a host: `retire` keeps every byte and is
undone by a deploy; `purge` deletes what the host holds and never reaches
offsite copies.

Release assets:

- `otostogan-platform-0.18.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.18.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform retire --project … --environment …` stops the application and
  its database containers, disables the backup timer, releases the domains
  through the same nginx transaction a deployment uses, and marks the scope
  `retired`. The database volume, local dumps, offsite copies, release
  bundles and ledger stay. `status` and `projects` say `retired`, reboot
  recovery leaves it down, `rollback` refuses, and a `deploy` clears the
  marker and brings the application back.
- `platform purge … --confirm-destructive`, only after `retire`: removes
  the database volume and network, the release bundles, the local dumps,
  the database credentials, the tmpfs secrets, the nginx ownership record
  and, last, the ledger. Offsite copies are never touched: the host's
  credential is write-only on purpose.
- The console offers Retire and Purge in the application menu with their
  gates; the handbook gains «Вывод приложения» and the two CLI cards.

Hosts: converge to pick up the runtime (`retire.py` is a new host module).
The `deploy` account's sudoers entry is unchanged; CI cannot retire or
purge.

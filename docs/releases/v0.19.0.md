# Platform Automation Core v0.19.0

An operator can reach a database with their own client through a tunnel
that closes itself, logging in as a throwaway role: the application's
credential never leaves the host.

Release assets:

- `otostogan-platform-0.19.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.19.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform database-session --project … --environment … [--minutes N]`
  creates a role `tunnel_<hex>`, member of `app`, valid for N minutes
  (default 30, at most 240), and prints the login with the container's
  address; expired session roles are swept on every open; `--close <role>`
  ends one at once. Only `ops` can run it.
- Console: «Database: tunnel for your own client» opens a session, runs
  `ssh -L 127.0.0.1:15432`, shows the fields for pgAdmin, TablePlus or
  psql and closes both the tunnel and the role on Enter, on timeout or on
  Ctrl-C. «Database: psql on the host» opens psql in the database container
  behind the handbook's full-rights warning.
- Handbook: the card and «Из консоли» notes on «Работа с базой».

Hosts: converge to pick up the runtime (`database_session.py` is a new host
module). Nothing changes for deployments.

# Platform Automation Core v0.20.0

Observability on the host: logs and metrics of everything that runs there,
under the platform's own labels, with one dashboard for every application.
Off until the inventory turns it on.

Release assets:

- `otostogan-platform-0.20.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.20.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- New role `observability`, enabled per host with `observability_enabled`.
  A collector (Alloy behind a read-only Docker socket proxy) and a backend
  (Loki, Prometheus, Grafana), each with its own unit; the collector writes
  by URL, so the backend can move to another machine by changing two
  inventory values. Nothing is published on the host.
- New host module `metrics_export`, run from a 30-second timer: container
  CPU, memory, network and restarts, and per project and environment the
  serving release, the domains it answers on, the newest dump and whether a
  restore was ever proven — written to a text file the collector reads.
- The proxy's JSON access log names the virtual host (`vhost`) and the
  request method; the built-in format had neither.
- Console: «Logs» (every service, the database, the proxy narrowed to the
  application's domains), «Grafana: open through a tunnel», a grouped action
  menu, and the nginx log filter that matches the JSON format.
- Handbook: «Наблюдаемость».

Hosts: convergence restarts the proxy once (new log format). The
observability role does nothing until `observability_enabled: true` and
`observability_grafana_admin_password_source` are set for the host.
Per-application metrics, traces, alerts and a backend that accepts remote
collectors are not in this release.

# Platform Automation Core v0.21.0

Alerts: the observability role now says when something is wrong, and the
console sets up where it says it.

Release assets:

- `otostogan-platform-0.21.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.21.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- Eleven alert rules, provisioned as files and evaluated by Grafana: a
  stopped container, a serving release with nothing running, a restart loop,
  memory near the limit, low disk, a stale dump, no dump at all, an unproven
  restore, the 5xx share per domain, platform metrics that stopped arriving,
  and an unreadable release ledger. Thresholds are inventory variables
  (`observability_alert_*`).
- Delivery to Telegram once `observability_alerts_telegram_token_source` and
  `observability_alerts_telegram_chat_id` are set. The token is a
  controller-local file and reaches Grafana only through its environment.
  Without a channel the rules still evaluate and show in Grafana.
- The metrics exporter reports `platform_backup_scheduled` and
  `platform_ledger_readable` per project and environment.
- Console: `Observability → Alerts: set up Telegram` on a host asks for the
  bot token (hidden) and the chat, proves both against the Bot API, sends a
  test message and writes the token file and the two inventory keys.

Upgrade: pin `v0.21.0`, converge. On hosts with observability enabled the
rules appear at once. A host whose dumps were never proven restorable will
raise "Restore is not proven" about an hour later; `platform verify-backup`
clears it.

Not covered: a host that is down entirely. Grafana runs on the host it
watches; only a check from outside sees that.

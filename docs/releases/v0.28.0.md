# Platform Automation Core v0.28.0

A memory limit for the platform-owned database.

Release assets:

- `otostogan-platform-0.28.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.28.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `database.resources` in the manifest limits the platform-owned database:
  `memory` becomes the container's `mem_limit`, and PostgreSQL learns of it
  through `shared_buffers` (the manifest's value, or a quarter of the limit)
  and `effective_cache_size` (two thirds). Shared memory grows with the
  buffers. `shared_buffers` is at most half of `memory`, `memory` at least
  `256m`, and the block is refused on an external database. Without the
  block the database stays unlimited, as before.

Upgrade: pin `v0.28.0`, converge. Then `platform update` in each
application: its deploy workflow is pinned to the release, and the runtime
of v0.27.0 refuses the new field. An application that wants the limit then
adds `database.resources` to its manifest and tags a new version; that
deploy recreates the database container with it.

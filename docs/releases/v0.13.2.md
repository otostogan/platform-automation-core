# Platform Automation Core v0.13.2

Makes `platform backup` work again. `v0.13.0` and `v0.13.1` cannot write a
dump at all, so scheduled backups have been failing since `v0.13.0`.

Release assets:

- `otostogan-platform-0.13.2.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.13.2-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- Writing the envelope meant feeding age's stdin from Python rather than
  wiring one process to the next, and the code then still called
  `communicate()`, which flushes stdin — already closed — and raises. Every
  dump failed with `ValueError: flush of closed file`. The pipeline now drains
  each stderr and waits, which is both the wait and the guard against a full
  pipe. Skip `v0.13.0` and `v0.13.1`.
- The sidecar's name is derived from the dump's rather than produced by
  substring substitution. A path not ending in the dump suffix previously
  resolved to the dump's own path, so the card would overwrite the thing it
  describes. Production names were always well formed, so this was a sharp
  edge rather than a live fault — the test that caught it was the first
  caller to use a different name.

Why this was the third defect in a row:

- All three hid behind test doubles that did not model process semantics: a
  descriptor a child inherits, a stdin that cannot be flushed once closed, a
  pipe that must be drained. The dump pipeline now has a test that runs it
  with **real processes**, using `cat` in place of `pg_dump` and age, so the
  pipes, closes and waits under test are the real ones.

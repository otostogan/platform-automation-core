# Platform Automation Core v0.13.1

Feeds `pg_restore` the dump. `v0.13.0` handed it an empty stream, so every
restore and every verification failed.

Release assets:

- `otostogan-platform-0.13.1.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.13.1-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `v0.13.0` read the envelope from a buffered file object and, finding none,
  seeked back to the start before handing that object to `pg_restore`. A
  buffered reader's `seek` restores the Python-level position but leaves the
  **file descriptor** wherever read-ahead put it — and a child process
  inherits the descriptor, not the buffer. `pg_restore` received nothing:
  `input file is too short (read 0, expected 5)`. Both restore paths failed,
  for both dump formats. Skip `v0.13.0`.
- The envelope is now parsed from the path and reported as an offset, and the
  caller seeks a raw descriptor to it. No buffering sits between the parse and
  the child.

Why the tests missed it:

- They exercised the parser against `BytesIO` and the restore against a fake
  runner, so no real process ever read from a real descriptor. Two tests now
  hand a positioned descriptor to an actual subprocess and assert the bytes it
  receives — for both an enveloped and a legacy dump.

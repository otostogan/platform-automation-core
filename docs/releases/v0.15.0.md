# Platform Automation Core v0.15.0

Adds `platform projects` on the host, and the first working slice of the
operator console on the workstation.

Release assets:

- `otostogan-platform-0.15.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.15.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- **`platform projects`** answers the first question anyone asks an unfamiliar
  host: what is here. One line per project and environment with a release
  ledger — the current deployed release, its status and healthcheck outcome,
  and how many records the ledger holds. Environments with no deployment yet
  are listed with a dash rather than omitted. `--json` gives the same for
  machines. It reads, changes nothing and takes no lock, so it is safe during
  a deployment. A stray entry under `/var/lib/platform/projects` is reported
  as `projects error: unexpected entry in projects root: …` rather than
  skipped, because reboot recovery walks the same tree before Docker is
  allowed to start.
- **The operator console.** On a workstation, `platform` with no arguments
  works out where it stands — an infrastructure repository, an application
  repository, or neither — from files on disk, and offers the matching
  actions with arrow-key selection. In an infrastructure repository it lists
  the hosts from the inventory and, for a chosen host, shows every project
  (through `projects`) or the status and backups of one. In an application
  repository it knows the project, its environments and the target host from
  the manifest and the deploy workflow, and can show the host's status and
  backups or validate the manifest and Compose contract locally. Every
  action prints the exact command before running it; actions not yet wired
  print only the command.
- **`platform doctor`** checks, before anything runs, what convergence would
  otherwise refuse later: the tailnet is connected and the host is online;
  the inventory user is `ops`; the SSH key and the host's age key exist, are
  not symbolic links, and are mode 0600; the installed collection matches the
  pin in `requirements.yml` and `ansible-core` satisfies the collection's
  requirement. In an application it validates the manifest and the Compose
  contract, confirms the secrets are SOPS-encrypted and counts recipients,
  checks the tailnet tag format, and compares the application's core pin with
  the infrastructure's when `~/.config/platform/config.yml` names the
  infrastructure repository — and says so when it cannot. Every failed check
  names the handbook page that explains it. `doctor` needs no terminal and
  works over a pipe.
- Interactive prompts come from the optional `[operator]` extra
  (`pip install 'platform-automation-runtime[operator]'`); the import is
  lazy, so hosts keep installing the wheel with its two dependencies.

The console holds no credentials: it reads paths from `local-secrets.yml`,
never keys, and connects with the operator's own SSH agent. On a host, bare
`platform` refuses and points at the subcommands; the `deploy` account's
sudoers entry is unchanged and still allows exactly `deploy`, `status` and
`rollback`.

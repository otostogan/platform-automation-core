# Platform Automation Core v0.22.1

A fresh database is asked whether it is ready in a way only the real server
can answer.

Release assets:

- `otostogan-platform-0.22.1.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.22.1-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- Fix a race in `verify-backup`. The readiness probe asked over the Unix
  socket, which answers while a fresh PostgreSQL container is still running
  its temporary initialisation server; the restore then met that server's
  shutdown and failed with "database restore failed" on a good dump. The
  probe now asks over TCP on 127.0.0.1.
- The same probe in the database's Compose healthcheck is fixed: on a
  brand-new volume a deploy could run migrations against the temporary
  server.

Upgrade: pin `v0.22.1`, converge. The next deploy of each application
recreates its database container once to pick up the healthcheck; the data
volume is untouched.

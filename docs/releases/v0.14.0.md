# Platform Automation Core v0.14.0

Adds the operator handbook: a guided, self-contained answer to "how do I do
this, and how do I know it worked" for every routine task on the platform.

Release assets:

- `otostogan-platform-0.14.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.14.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `docs/handbook.html` is new. It is one file: no build step, no external
  requests, opened straight from disk or from a browser. Two ways in — a task,
  or a term.
  - **Tasks** are guided flows rather than prose. A flow states what you need
    on hand before step one and refuses to start until you confirm you have it;
    it asks where you are starting from and skips what you have already done;
    it shows one step at a time and remembers where you stopped. Every step
    that gives a command also says, in the same place, how to tell that the
    command worked — the literal output to expect — and what the known failures
    look like, quoting the message the platform actually prints and saying
    whether the failure left anything half-changed.
  - **Reference** covers the `platform/v1` manifest field by field, the Compose
    contract, every inventory variable, the key material and who holds which
    half, the release ledger, the layout of a converged host, and each CLI
    command with its flags. Terms link to a glossary that opens beside the text
    without losing your place in a flow.
  - Anything that happens in someone else's web interface — the Tailscale
    console, GitHub settings, the hosting provider — names the click path and
    the stable URL, not just the setting.
  - Concrete values come from a context panel. The handbook itself contains
    only placeholders, as the repository boundary check requires; the reader
    enters their own host, project, environment and domain once, and every
    command on every page re-renders with them, ready to copy.
  - Claims derived from reading the code but never exercised on a live host are
    marked as such, in place, each with the experiment that would settle it.
    The register collects them automatically, so it cannot drift from the text.
- `README.md` now leads with what the platform does and the rules that enforce
  it — deployment by digest, plaintext secrets only in `tmpfs`, a CI account
  limited to three commands, convergence only over the tailnet, default-deny
  ingress — instead of listing what the repository contains.
- `docs/qa-digest.md` named the server tag `tag:platform-server`. That tag does
  not exist; the inventory advertises `tag:server-platform`. An operator
  following the digest would have issued an auth key carrying a tag that no
  access rule matches. The bootstrap document in the infrastructure repository
  carries the same mistake and needs the same correction.

Nothing in the runtime, the roles, or the contracts changed. A host converged
with `v0.13.3` behaves identically under `v0.14.0`; the version moves because a
new deliverable ships with the release, not because behaviour did.

# Platform Automation Core v0.25.0

Applications ship their own dashboards with their releases.

Release assets:

- `otostogan-platform-0.25.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.25.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `observability.dashboards` in the manifest: a directory of Grafana
  `*.json` files. The serving release's dashboards are shown in a Grafana
  folder named `<project>-<environment>`; a rollback shows the dashboards of
  the release rolled back to, and a retired application's folder goes away.
- A dashboard may read only `platform-prometheus` and `platform-loki`. Its
  `uid` is set by the platform and it is not editable in the UI. Up to 20
  dashboards, 512 KiB each, 4 MiB together.
- The deployment bundle may carry a fourth file, generated from that
  directory and verified by its SHA-256 like the other three. A bundle
  without dashboards is unchanged, byte for byte.
- `platform doctor` and the console's validation check the dashboards
  before a deploy.
- A ledger, a scope or a bundle that cannot be read is no longer taken for
  "nothing shipped": dashboards and scrape targets stay as they are until it
  reads again.

Upgrade: pin `v0.25.0`, converge. Then, in each application, `platform
update` before adding `observability.dashboards`: a host or a workflow on an
older core rejects the field and a five-file bundle. The convergence
restarts Grafana once.

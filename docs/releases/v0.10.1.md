# Platform Automation Core v0.10.1

Makes the scheduled backup unit actually run. `v0.10.0` installs a timer
whose service fails on every trigger.

Release assets:

- `otostogan-platform-0.10.1.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.10.1-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- The `v0.10.0` unit split the systemd instance into a project and an
  environment using shell parameter expansion. systemd resolves `${...}` in
  `ExecStart` itself, before any shell sees it, so it read those as references
  to its own environment variables, found them unset, and substituted empty
  strings. Every scheduled run reached the CLI as `--environment ''` and
  exited 2. Skip `v0.10.0` for scheduled backups.
- `platform backup` now takes `--instance {project}-{environment}` directly,
  and the unit runs the CLI with no shell at all. The parsing moves to
  `split_instance`, which already validated both halves and was already
  covered by tests — it simply was not the code doing the work.
- A structural test now refuses shell parameter expansion in any unit's
  `Exec*` line. Nothing without a real systemd can observe the substitution
  itself, but the syntax that causes it can be rejected outright.

`platform backup --project X --environment Y` is unchanged.

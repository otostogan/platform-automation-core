# Platform Automation Core v0.8.0

Produces encrypted, self-describing database dumps, and stops the platform
from improvising around a volume that already holds data.

Release assets:

- `otostogan-platform-0.8.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.8.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform backup` writes one encrypted dump of a platform-owned database.
  `pg_dump` is piped straight through age into its destination, so the
  plaintext exists only in that pipe and never on disk; a failed dump or a
  failed encryption leaves nothing behind.
- Dumps are encrypted to the same age recipients as the application's own
  secrets, escrow included. A backup inherits the bus factor of everything
  else rather than growing its own.
- The filename carries only a timestamp and a reason — `operator`,
  `schedule`, or `pre-migration`. Everything else lives in a metadata card
  beside the dump and inside the encrypted stream, so a dump found alone
  describes itself once decrypted, which it must be to be used at all. The
  application version deliberately stays out of the filename: object keys are
  readable by anyone who can list a bucket. The card keys on `release_id`
  rather than the release tag, because a tag is a human label and may be
  anything.
- Local retention honours `database.backup.retain`: it drops the oldest dumps
  beyond that count, never the newest, and only ever warns.
- The `secrets` role installs a pinned `age` binary alongside SOPS. SOPS
  encrypts structured documents; a database dump is an opaque stream, and
  inflating one inside a JSON envelope is the wrong shape for it.

Guards around an existing volume:

- Changing `postgres_major` while a volume exists is refused. Data does not
  move between majors on its own, and PostgreSQL 18 changed where the cluster
  lives inside the volume, so the old one would simply be ignored. The
  supported path is dump, remove, restore.
- A volume whose credential file has gone missing is refused. A freshly
  generated password never reaches a database that already exists —
  `POSTGRES_PASSWORD` only applies while initialising an empty volume — so
  the application would fail to authenticate against a deploy that reported
  success, and `pg_isready` would not notice.

Restoring a dump is not implemented yet; until it is, a backup is unproven.

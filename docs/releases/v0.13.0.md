# Platform Automation Core v0.13.0

Makes a dump describe itself, and gives the database credential a way to
change.

Release assets:

- `otostogan-platform-0.13.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.13.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- The metadata card now travels **inside** the encrypted stream as well as
  beside it. `v0.8.0` claimed this and did not do it, so a dump downloaded
  without its sidecar was an opaque `PGDMP` blob. The stream opens with one
  readable line, `PLATFORM-BACKUP/1 <length>`, followed by the card and then
  the untouched `pg_dump` bytes — legible to someone holding nothing but
  `age`, and streamable in constant memory. Tar was the obvious container and
  is the wrong one: it needs a member's size before its data, and a dump's
  size is not known until it has finished.
- `platform restore` reads both formats. Dumps written before the envelope
  existed begin with `pg_dump`'s own magic and are fed whole; a backup that
  stopped restoring because the format improved would not be an improvement.
  When a stream carries a card, that card wins over the sidecar — it travelled
  with the data rather than beside it.
- New `platform rotate-database-password`. It changes the database first, then
  the stored credential, then restarts the application so it picks up the new
  URL. That order is deliberate: a stored credential that no longer opens the
  database is a worse failure than a database whose new password is not yet
  stored, because the second is visible immediately and the first is not.
- Rotation requires `--confirm-disruptive`, takes the project lock, and
  refuses for an external database. A restart that fails after the password
  changed is reported with the recovery step rather than left silent.

No contract changes. Existing backups remain restorable.

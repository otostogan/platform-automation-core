# Platform Automation Core v0.11.0

Carries encrypted dumps off the host that made them.

Release assets:

- `otostogan-platform-0.11.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.11.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- Every backup run uploads dumps to object storage when a host is configured
  for it. The upload **reconciles rather than pushes**: it sends whatever
  local dump is missing remotely, not merely the one just taken. Enabling
  offsite storage therefore carries the existing dumps up on the first run,
  and an upload that failed yesterday is retried today instead of being lost.
  The work is bounded by local retention.
- A host with no offsite configuration keeps its backups local. That stays a
  supported answer rather than an error.
- Nothing readable leaves the host: dumps are already encrypted to the
  application's own age recipients. Object keys carry no application version,
  because they are readable by anyone who can list the bucket.
- The host credential is write-only by design, and the platform never deletes
  remotely: remote retention belongs to a bucket lifecycle rule. A backup an
  attacker can erase only protects against a failed disk.
- **A failed upload fails the command.** Retention and scheduling only warn,
  because they tidy up around work that already succeeded; a host that has
  quietly stopped uploading is the failure discovered too late. The dump still
  succeeded and stays on disk for the next run to carry up.
- `platform status` reports whether offsite storage is current, behind, or not
  configured, and names the backups that have not reached the bucket.
- `platform restore --from-offsite` fetches a dump and its card back before
  restoring. Reader credentials arrive on standard input, the same way a
  registry token reaches a deployment, and never land on the host.
- The `platform_cli` role installs `python3-boto3` from apt, alongside the
  other runtime packages. No bundled CLI is added to the host.
- Offsite settings are named `platform_cli_offsite_*`, following the same
  role-prefixed convention as every other variable in the collection. They are
  deliberately not named for S3: the endpoint is configurable, and any
  compatible object store works.

Boundary policy:

- The `aws_secret_access_key` rule matched the name rather than a value, and
  that name is unavoidable in any code that talks to S3 — it is a boto3
  keyword argument. It now matches an assignment of something the length and
  shape of a real key. A new test asserts a realistic key is still caught
  while naming the argument is not.

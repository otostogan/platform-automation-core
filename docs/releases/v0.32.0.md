# Platform Automation Core v0.32.0

A backup moves from one host to another, a retired host stays in the
inventory, and the console deploys without GitHub when it must.

Release assets:

- `otostogan-platform-0.32.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.32.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform backup-import` on the host takes a dump re-encrypted to this
  host's recipients on standard input, proves with its own identity that
  the envelope opens, and stores it under the original stamp with
  `imported_from`. The console's application menu gains "Backups: move one
  here from another host": the dump is fetched from a host of any
  registered infrastructure, re-keyed on the workstation with the source
  host's identity, handed to the target host, and the ordinary restore is
  offered.

- The backup tables show when each dump was taken and how old it is, next
  to the stamp.

- A host can be retired into a `retired_hosts` inventory group: described
  and remembered, targeted by nothing; `platform doctor` lists it dim.
  `platform new host` works when the only host is retired and takes its
  defaults from it.

- The console deploys without GitHub as a break-glass action: image built
  and pushed here, bundle built here, `platform deploy` run on the host
  with the operator's own registry login; refused on a dirty tree or off a
  release tag, and while GitHub answers unless `break-glass` is typed.

- `platform secrets push` lets a staged `.env.example` through, as the
  pre-commit hook already did.

Upgrade: pin `v0.32.0`, converge. A host on an older core has no
`backup-import`; move backups only after the target host is converged.
Applications: `platform update` is optional, no managed file changed.

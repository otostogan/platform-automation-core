# Platform Automation Core v0.3.3

Documents the readiness role, whose phase parameter silently halved the audit.

Release assets:

- `otostogan-platform-0.3.3.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.3.3-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `roles/vps_readiness/README.md` documents every variable, both phases, and
  the consequence of the default. `vps_readiness_phase` defaults to `pre`,
  which audits the machine and skips every check covering what convergence
  built — systemd units, firewall policy, Docker forwarding chains, exposed
  ports, proxy health — while still reporting
  `All automated VPS readiness checks passed`. The parameter appeared in no
  documentation at all, so the weaker result looked like the complete one.
- The runbook and collection guide now name the phase in the acceptance
  sequence rather than saying only "run readiness".
- Tests assert that every default is documented and that the documented values
  match the role, so the README cannot drift back out of sync.

No behavior changes. Consumers running readiness after convergence should pin
`vps_readiness_phase: post` in their inventory.

# Platform Automation Core v0.16.0

The operator console grows from reading to writing: it creates infrastructure
repositories, hosts and applications from the handbook's own templates, keeps
application files up to date, and turns secrets into a plain `.env` file the
operator edits.

Release assets:

- `otostogan-platform-0.16.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.16.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform new app` writes an application's platform files — manifest per
  environment, Compose file, `.sops.yaml`, three workflows, three hooks,
  `.gitignore` — from the templates the handbook shows, with the host, the
  recipients and the core pin taken from the registered infrastructure. The
  result is validated the way a deployment would validate it. An existing
  `.gitignore` is appended to; every other existing file stops the scaffold.
- Secrets are edited as `.env.<environment>` files, never as SOPS documents.
  A `pre-commit` hook calls `platform secrets push`, which encrypts the file
  into the committed ciphertext with the rules the host applies and stages
  it; plaintext is refused from the index. `platform secrets pull` reads a
  file back for a key holder. `doctor` checks the hooks, the ignore rule and
  staleness.
- `platform update` rewrites the platform-owned files of an application from
  the current templates and the infrastructure's pin and recipients, after a
  diff and a confirmation. Ownership is a first-line `# platform-managed`
  marker; files without it are only diffed. It refuses when the console is
  newer than the hosts.
- `platform new host` adds a host to an infrastructure: age key generated,
  both inventories appended as text with comments intact and parsed back
  before writing, `host_vars` paths written, recipient published.
- `platform new company-infra` starts an infrastructure repository from an
  empty directory: operator SSH key and both age keys generated, pin to this
  version, inventories with the first host, group policy, key paths,
  documents; `git init`, registry entry, an offer to build the venv.
- The console keeps a registry of infrastructure repositories in
  `~/.config/platform/config.yml` (paths only) and fills it itself; `platform
  infra list|add|forget` manages it. The console stays open after an action.
- Handbook: the secrets step describes the `.env` path; recipient rotation
  goes through `platform update`; «Обновление ядра» gains the step that
  brings applications up to the new templates; «Новый хост» and «Карта
  хоста» say what the console now does.

Hosts: nothing in the runtime, the roles or the contracts changes behaviour.
A host converged with `v0.15.1` behaves identically under `v0.16.0`; the
version moves because the workstation console and the pinned reusable
workflows do. After converging, run `platform update` in each application so
its `deploy.yml` pins `v0.16.0`.

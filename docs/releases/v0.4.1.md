# Platform Automation Core v0.4.1

Installs the retention module on the host. Convergence with `v0.4.0` fails
without it.

Release assets:

- `otostogan-platform-0.4.1.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.4.1-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- The `platform_cli` role copies a named list of runtime modules to the host,
  and `release_retention.py` was not on it. The server CLI imports that module,
  so converging a host to `v0.4.0` installed a CLI that cannot start. The role
  validates the installed CLI before finishing, so the failure was loud rather
  than silent, but `v0.4.0` cannot be converged and should be skipped.
- `bundle_action.py` was on that list and should not have been. It is the
  `platform-prepare-bundle` entry point, it runs in CI from the wheel, and it
  imports `build_bundle`, which the host does not have. Nothing on the host
  imported it, so it was inert rather than harmful. Convergence does not remove
  files it no longer installs, so the stale copy stays under the CLI install
  root on hosts converged before this release; it is unreferenced and safe to
  delete by hand.
- A structural test now walks the runtime package and fails when a module is
  neither installed by the role nor declared controller-only, when the role
  installs a module that no longer exists, when an installed module imports a
  controller-only one, and when a contract file is missing from the role. The
  first two conditions are what went wrong here.

No behavior changes on a host that is already running.

# Platform Automation Core v0.7.0

Builds the deployment bundle from the commit the image was built from, so a
release can no longer ship a new image with an older manifest.

Release assets:

- `otostogan-platform-0.7.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.7.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- The reusable deployment workflow checked out whatever branch the calling
  workflow ran from, while the image came from the revision the operator
  asked to deploy. Whenever those differed, the host received a bundle whose
  manifest, Compose model, and encrypted secrets belonged to a different
  revision than the running image — and reported success. The mismatch stays
  invisible for as long as an application's deployment files do not change,
  which is exactly how long it takes to trust the deployment.
- `application_commit` is a new **required** input naming the commit the
  bundle is built from. It is validated as a full 40-character SHA and
  refused otherwise: a branch or tag can move between resolving the image and
  building the bundle, and only a commit cannot.

Breaking:

- Callers of `reusable-deploy.yml` must pass `application_commit`. Pass the
  commit the deployed image was built from — the same one used to look the
  image up. `examples/consumer` shows the shape.

# Platform Automation Core v0.5.0

Shapes the backup contract before anything implements it, so the phases that
follow are additive rather than breaking.

Release assets:

- `otostogan-platform-0.5.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.5.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Contract:

- `database.postgres_major` accepts 16, 17, or 18 instead of exactly 17. The
  platform will run the container and its own dump tooling, so the set is
  limited to majors it is known to operate; widening it later is additive,
  narrowing it would not be.
- New `database.backup` object with two required fields: `interval_minutes`
  (15 to 1440) and `retain` (1 to 100). The lower interval bound exists
  because a project asking for a dump every minute starves the disk and IO of
  every other project on the host; the upper bound exists because a live
  database backed up less than daily is neglect the contract should refuse to
  encode. Both bounds start deliberately tight — loosening later is additive.
- `backup_enabled` remains the switch, and the `backup` object must be present
  exactly when it is true. A manifest can neither promise a backup while
  withholding its cadence, nor carry a backup configuration that nothing will
  ever read. The existing rule that an external database cannot enable
  platform backups is unchanged.
- The object shape leaves room for a future `strategy` field (dumps versus
  dumps plus WAL archiving); adding a key to an object later is additive,
  bolting configuration onto a bare boolean would not have been.

Nothing implements the new fields yet — that is the next phase. Existing
manifests, including both live medkeep manifests, validate unchanged.

No behavior changes on any host.

# Platform Automation Core v0.13.3

Makes `platform rotate-database-password` work, and stops it putting the new
password on the command line.

Release assets:

- `otostogan-platform-0.13.3.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.13.3-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- The rotation in `v0.13.0` sent `ALTER USER app WITH PASSWORD :'password'`
  through `psql --command`. **psql interpolates variables only for input it
  reads, not for `--command`**, so the placeholder arrived as literal SQL and
  every rotation failed with a syntax error. The statement now goes in on
  standard input, where interpolation happens.
- That also removes the password from `argv`, where any user on the host
  could read it with `ps`. It travels on the same stdin as the statement.
- The generated password is checked against a conservative alphabet before it
  reaches SQL. `token_urlsafe` has always stayed inside it; asserting it means
  a later change to the generator cannot quietly turn an interpolation into an
  injection.

Rotation was introduced in `v0.13.0` and has never worked until now, so
nothing depended on the previous behaviour.

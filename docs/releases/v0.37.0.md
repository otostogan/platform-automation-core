# v0.37.0

Minor release: the environments of one application may live on different
hosts.

## Added

- `platform update --host <environment>=<host>` moves one environment to
  another host. `target_host` in the application's `deploy.yml` becomes a
  lookup by the dispatched environment, and later updates read the hosts
  back from it.
- `.sops.yaml` gets a rule per environment when the hosts carry different
  keys: each secrets file is encrypted for the host it is deployed to and
  for the recovery key of that host's infrastructure. Only the moved
  environment is re-encrypted.
- The console menu, `platform doctor` and `platform secrets pull` address
  the host of the chosen environment; doctor reports target host, core pin
  and recipients per host.

## Changed

- With several hosts the workflow's core pin follows the oldest of them.
- An application on one host is rendered exactly as before, and
  `reusable-deploy.yml` is unchanged.

## Upgrade

- Workstation: reinstall the console wheel from this release.
- Hosts: no runtime change. `platform update` in an application refuses
  while a host it deploys to is pinned below the console, so converge with
  the 0.37.0 collection before rewriting application workflows.

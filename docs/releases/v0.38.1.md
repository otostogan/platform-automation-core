# v0.38.1

Patch release: `platform new app` sets up an application in a monorepo in
one pass.

## Changed

- In a workspace repository — `pnpm-workspace.yaml`, `turbo.json`,
  `nx.json`, `lerna.json`, or `workspaces` in the root `package.json` — the
  wizard asks which `package.json` carries the application's version and
  how its release tag starts, and writes the workflows and hooks for both.
  It offers the root file and every workspace package with a version, and
  suggests the prefix from the directory name: `apps/crm` gives `crm-v`.
  The separate `platform update --version-file … --tag-prefix …` is no
  longer needed for a new application.
- Changing the version file on the review screen brings the prefix
  suggested for it, so a workspace application is never left with the
  repository-wide `v` tag.
- A repository that is the application is asked nothing new.

## Upgrade

- Workstation: reinstall the console wheel from this release.
- Hosts: no runtime change. `platform update` in an application still
  refuses while a host it deploys to is pinned below the console, so move
  the pin to 0.38.1 and converge before rewriting application workflows.

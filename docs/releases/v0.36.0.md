# Platform Automation Core v0.36.0

Scheduled SQL exports by e-mail.

Release assets:

- `otostogan-platform-0.36.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.36.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- A manifest with `database.mode: docker` may declare `exports`: an SMTP
  relay whose password is named by `password_env` and read from the
  release's secrets, and up to twenty jobs with a name, a systemd calendar
  `schedule`, recipients and a query. The host runs the query in the
  database container as the application's role, in a read-only transaction
  limited to ten minutes, streams the result under a 64 MB cap and mails
  the CSV over TLS. A deploy writes one
  `platform-export@<project>-<environment>-<name>.timer` per job and
  removes the timers of jobs that left the manifest; `retire` and `purge`
  remove them all. `platform export` runs a job now, `platform exports`
  and `platform status` show each job's last run, the **Export failed**
  alert fires when a scheduled job's last run did not send, and the console
  gains "Exports: list and last runs" and "Exports: send one now".

Upgrade: pin `v0.36.0`, converge (installs the export units and creates
`/var/lib/platform/exports`). Applications need no change until they
declare `exports`; then add the SMTP password to the environment secrets
and deploy.

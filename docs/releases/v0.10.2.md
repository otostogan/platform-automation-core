# Platform Automation Core v0.10.2

Makes the scheduled timer compute a next run. `v0.10.0` and `v0.10.1` install
a timer that fires once and never again.

Release assets:

- `otostogan-platform-0.10.2.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.10.2-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- The interval drop-in reset the timer list twice — once before
  `OnUnitActiveSec` and again before `OnBootSec`. In systemd an empty
  assignment resets the **entire** list of monotonic timers rather than the
  single option it names, so the second reset discarded the interval the first
  pass had just set. Only `OnBootSec` survived, which elapses once relative to
  boot and never repeats: `systemctl list-timers` showed no next elapse at all.
  The drop-in now resets once, before both values.
- `Persistent=true` is removed from the timer. It only has an effect on
  calendar timers, so on a monotonic timer it was inert while the
  documentation claimed it caught up after downtime. The runbook now says what
  actually happens: a host that was switched off resumes rather than replaying
  missed windows, and `platform status` is where a long gap shows.

Both defects were only observable against a real systemd. A test now asserts
the drop-in carries exactly one reset, and that it precedes every value.

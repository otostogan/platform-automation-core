# Platform Automation Core v0.24.0

Applications publish their own metrics, and the console covers the whole
life of a host.

Release assets:

- `otostogan-platform-0.24.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.24.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `service.metrics` in the manifest: a `path` and a `port` on the web
  service. The platform scrapes the endpoint every thirty seconds on each
  web container of the serving release and labels the series itself — host,
  project, environment, service, container; what an application says under
  those names is kept as `exported_*`. The port must be in the web service's
  `expose`; a path with a `.` or `..` segment is rejected.
- The endpoint is never public: on the proxied port the proxy answers 404
  for the path on the web service's domains.
- Series named `platform_*` or `node_*` from an application are dropped, and
  a scrape of more than 10 000 samples is refused.
- New alert "Application metrics not collected".
- The collector joins the proxy's network to reach the endpoints. Nothing
  new is published on the host.
- Console: `Bootstrap: first run on a new host` — from the provider's SSH
  through the tailnet handover to readiness; `platform infra` alone lists.
- Handbook: a page for the operator console.

Upgrade: pin `v0.24.0`, converge. Then, in each application, `platform
update` before adding `service.metrics`: a host or a workflow on an older
core rejects the field. The convergence restarts the collector once.

# v0.38.0

Minor release: an application that lives inside a monorepo.

## Added

- `platform update --version-file <path> --tag-prefix <prefix>` says where
  the project's version lives and how its release tag starts: `crm-v` gives
  `crm-v1.2.3`. The build, release and deploy workflows and the three hooks
  follow both, and later updates read them back from `release.yml`. With a
  prefix, an empty ref deploys this application's newest release rather
  than the repository's, rollback resolves the prefixed tag, and the
  pre-push hook leaves other projects' tags alone.
- A repository whose hooks lefthook runs keeps them. The console no longer
  points `core.hooksPath` at `.githooks` there; the platform's scripts stay
  in `.githooks/` and are run from the lefthook file. `platform doctor` and
  `platform update` name the hook it does not run yet.

## Changed

- The pre-commit hook asks for the console only when a local
  `.env.<environment>` exists, so a contributor who never touches secrets
  needs no `platform` binary. Applications pick this up with their next
  `platform update`.
- The defaults, `package.json` and `v`, render every other template exactly
  as before.

## Upgrade

- Workstation: reinstall the console wheel from this release.
- Hosts: no runtime change. `platform update` in an application refuses
  while a host it deploys to is pinned below the console, so move the pin
  to 0.38.0 and converge before rewriting application workflows.

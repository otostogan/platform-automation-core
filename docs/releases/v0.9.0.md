# Platform Automation Core v0.9.0

Reads backups back, and proves that reading them back works.

Release assets:

- `otostogan-platform-0.9.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.9.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform verify-backup` decrypts a dump, restores it into a throwaway
  container with no network, runs the query the application declared in
  `restore_validation`, and removes the container whether or not any of that
  worked. The live database is never touched. The container briefly holds a
  full plaintext copy of the data, which is why it gets no network and why
  nothing it writes outlives it.
- Every verification is recorded, success or failure, and `platform status`
  now reports when a restore was last *proven* rather than when a dump was
  last taken. Those are different questions, and only the first one matters
  during an incident.
- `platform restore` replaces the contents of the live database from a dump.
  It requires `--confirm-destructive`, and it refuses while a deployment holds
  the project lock, so a restore cannot land underneath a migration in flight.
- A dump taken on a different release than the one deployed is reported, not
  refused. Restoring across a revision is sometimes exactly what an operator
  means to do — but the schema lives inside the dump, so the mismatch is named
  in both directions before the operator walks away.
- Backups are selected by stamp or default to the newest. A stamp that is not
  a well-formed backup name is refused rather than resolved.

The backups written by `v0.8.x` are now provable. Scheduling them is the next
phase; until then every dump is taken by an operator.

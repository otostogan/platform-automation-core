# Platform Automation Core v0.4.2

Lets rollback and reboot recovery work when the registry is unreachable,
which is the situation they exist for.

Release assets:

- `otostogan-platform-0.4.2.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.4.2-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform rollback` contacted the registry for both the target and the
  current release even though retention keeps exactly those images on the
  host. A private registry refuses an anonymous pull, so the host-side
  rollback path — the one meant for a failed CI, an unreachable registry, or
  no outbound network — could not run without registry credentials. The image
  is now fetched only when the daemon does not already hold that digest.
- The same probe applies to `platform deploy`. Redeploying a retained version,
  which is how a rollback is normally performed, no longer re-fetches an image
  that is already on the host.
- A reference carrying a sha256 digest names one immutable manifest and Docker
  records such a reference only for content it pulled, so a local hit is as
  trustworthy as a fresh fetch. A probe that cannot be answered — no daemon, a
  timeout — is never read as "already present"; it falls back to a pull.

No contract changes.

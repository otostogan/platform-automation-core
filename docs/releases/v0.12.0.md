# Platform Automation Core v0.12.0

Makes the backup machinery legible to someone who did not build it.

Release assets:

- `otostogan-platform-0.12.0.tar.gz` — Ansible Collection
  `otostogan.platform`.
- `platform_automation_runtime-0.12.0-py3-none-any.whl` — Python runtime and
  controller utilities.
- `SHA256SUMS` — integrity checks for both installable artifacts.

Changes:

- `platform status` states the loss window: how old the newest dump is, what
  cadence is configured, and therefore how much data an outage right now would
  cost. An operator was previously left to do that arithmetic on a timestamp,
  at the worst possible moment.
- When the newest dump is more than twice the configured interval old, status
  says the schedule has stopped rather than quoting a window that is no longer
  bounded by anything. The slack is deliberate: timers carry a randomised
  delay, and an alarm that cries wolf is an alarm that gets ignored.
- New `platform backups` command: one row per dump, newest first, with when it
  was taken, why, how large, which release it came from, whether it reached
  object storage, and whether a restore from it has been proven. A damaged
  metadata card costs one column rather than the whole listing.
- Status survives a manifest it cannot read: an unreadable bundle costs the
  schedule line, not the report.
- The runbook is reordered for the moment it is opened. Emergencies first —
  restoring, a stuck release, rollback, blocked convergence — then routine
  operations, then how the machinery behaves, then setup, which is read once
  and never in a hurry. Its opening now states the two things worth knowing
  before anything else, including that **a rollback does not roll back data**.
- The restore procedure now begins by finding the dump rather than assuming
  the operator already knows its name.

Not included: the second-operator drill, which needs a second operator with
their own object-storage credentials.
